## 代码核查发现的首要未决冲突

`app/src/main/kotlin/com/app/crypto/KeystoreCryptoProvider.kt` 生成的 Android Keystore 私钥按平台设计不可导出，但 `KeyManagementScreen.kt` 同时向用户提供“导出私钥”和“私钥二维码”。`exportPrivateKey()` 对 Keystore 原生私钥读取 `encoded`，通常得不到可导出的 PKCS#8 数据。因此“硬件保护”和“生成后可备份/迁移”不能按当前实现同时成立。

私钥二维码还会显著增加误泄露风险。这个决策会进一步决定：

- 密钥生成和存储模型
- 换机、卸载、设备损坏后的恢复方式
- 是否保留私钥导出/二维码 UI
- 生物认证与备份口令设计
- 历史密文能否长期解密

## 已确认的新决策

### 1. 密钥可移植性与基本操作

- 本机私钥不可导出。
- 公钥允许导出。
- 支持生成新密钥：生成新私钥，并由该私钥推导对应公钥。
- 支持删除密钥；删除操作必须同时删除对应的私钥和公钥。
- 应删除当前界面的“导出私钥”和“私钥二维码”功能。

### 2. 已有密钥时禁止生成

- 应用采用单密钥槽。
- 只要设备中已有密钥，便不允许生成新密钥。
- 不提供静默覆盖、替换或密钥轮换入口。
- 用户只有先删除现有公私钥，才能重新生成密钥。

### 3. 删除密钥保护

- 删除前显示明确警告：“历史密文将永久无法解密”。
- 随后调用 Android 系统身份验证，允许生物识别或锁屏密码。
- 只有验证成功才执行删除。
- 删除操作必须同时删除私钥和公钥。

### 4. 私钥解密授权窗口

- 首次解密文件或文本前，要求 Android 生物识别或锁屏密码验证。
- 验证成功后，5 分钟内允许连续解密。
- 超过 5 分钟后必须重新验证。
- 应用进入后台时立即清除授权状态；返回应用后必须重新验证。

### 5. 禁止导入私钥

- 不允许通过文件、剪贴板、文本粘贴或二维码导入外部私钥。
- 删除当前所有“导入私钥”入口及相关软件私钥存储代码。
- 应用只使用 Android Keystore 内生成的本机不可导出私钥。

### 6. 公钥只导出二维码 PNG

- 公钥只允许导出为二维码 `.png` 文件。
- 不提供复制 PEM 公钥文本。
- 不提供普通公钥文本文件。
- 不提供 `.fstpub` 公钥文件。

### 7. 公钥二维码兼容格式

- 二维码内容使用与 Java 端完全相同的生成和解析方式。
- 载荷采用 Java `KeyArtifactPayload` 定义的 `FST-PUB1:` 格式。
- 不创建 Android 专用公钥二维码格式。

### 8. 联系人公钥二维码输入

- 支持摄像头实时扫描 `FST-PUB1` 公钥二维码。
- 支持通过系统文件选择器选择已有的二维码 `.png`。
- 解析成功后先显示公钥指纹，用户确认后才保存联系人。
- 不提供手工粘贴公钥。

### 9. 联系人唯一身份

- 使用公钥的 SHA-256 指纹作为联系人不可修改的唯一标识。
- 指纹算法必须与 Java 端 `CryptoEngine.fingerprintPemText` 完全一致：对规范化 PEM 文本的 UTF-8 字节计算 SHA-256。
- 显示名由用户填写，保存后允许修改。
- 同一指纹只能对应一个联系人。
- 再次扫描已有指纹时打开现有联系人，不创建重复记录。

### 10. 联系人显示名

- 显示名必填。
- 保存前去除首尾空白。
- 长度限制为 1–40 个 Unicode 字符。
- 不要求显示名唯一；不同联系人可以重名。

### 11. 删除黑名单功能

- 删除联系人黑名单页面和所有入口。
- 删除 `BlacklistEntity`、`BlacklistDao` 及 Repository/ViewModel 中的黑名单逻辑。
- 删除相关数据库表、字符串资源和测试。
- 联系人系统只负责保存可供加密选择的公钥联系人。

### 12. 删除联系人确认

- 删除前显示一次确认对话框。
- 对话框显示联系人名称和公钥指纹末 8 位。
- 用户确认后立即删除。
- 不要求生物识别或锁屏密码。

### 13. 允许加密给本机

- 文件和文本加密的接收者列表包含“自己（本机公钥）”。
- “自己（本机）”固定显示在联系人之前。
- FST2/FST-TEXT1 继续保持一次只能选择一个接收者。

### 14. 接收者必须明确选择

- 打开文件或文本加密页面时，不默认选中任何接收者。
- 用户必须明确选择接收者后，加密按钮才可用。
- 可选接收者来源为：
  - 自己（本机公钥）；
  - 已保存联系人；
  - 用户从系统文件选择器选择的公钥二维码 PNG。
- 临时选择只接受 `.png`；不接受其他图片格式、文本、PEM 或 `.fstpub` 文件。

### 15. 临时二维码接收者

- 加密页面选择的公钥二维码 PNG 默认只用于当前一次加密。
- 解析后显示该公钥指纹。
- 不自动写入联系人数据库。
- 提供独立的“保存为联系人”按钮。
- 用户点击该按钮并填写符合规则的显示名后，才保存联系人。

### 16. 单文件处理

- 文件加密一次只选择并处理一个输入文件。
- 文件解密一次只选择并处理一个 FST2 文件。
- 首个版本不实现多选、批量队列或并行文件处理。

### 17. 输出重名策略

- 永不覆盖已有输出文件。
- 文件加密重名时，在原文件名与 `.fst2` 之间追加递增编号，例如：
  - `report.pdf.fst2`
  - `report.pdf (1).fst2`
- 文件解密重名时，在基本名称后、扩展名前追加递增编号，例如 `report (1).pdf`。

### 18. 始终保留输入文件

- 加密成功后保留原始明文文件。
- 解密成功后保留输入 FST2 密文文件。
- 应用不提供或执行自动删除输入文件的行为。
- 用户需要删除时自行通过系统文件管理器处理。

### 19. 文件任务进度、取消与失败清理

- 文件加密和解密显示按已处理字节计算的进度条与百分比。
- 运行期间提供取消按钮。
- 取消应在安全的块边界尽快生效。
- 取消或失败时关闭输入输出流，并删除未完成的输出文件。
- 不保留无法正常使用的部分 FST2 或部分明文文件。

### 20. 后台文件任务

- 文件加密或解密任务在应用进入后台或屏幕熄灭后继续运行。
- 使用 Android 前台服务执行并显示常驻通知。
- 通知显示任务名称、进度和取消操作。
- 任务完成、失败或取消后结束前台服务。
- 应用进入后台会清除后续解密的授权窗口。
- 已经完成身份验证并启动的单个任务不因授权窗口清除而中断。

### 21. 单一文件任务

- 全局同一时间只允许一个文件加密或解密任务。
- 任务运行期间禁用其他文件加密和解密按钮。
- 提供“查看当前任务”入口，返回任务进度与取消界面。
- 文件任务运行时，文本加密和解密仍可使用。
- 首个版本不实现文件任务队列。

### 22. 文件大小与空间检查

- 不设置人为文件大小上限。
- 文件始终使用流式分块方式处理，不将完整内容读入内存。
- 可获知输入大小时，开始前估算输出空间并检查可用存储。
- 空间不足时不启动任务，并显示预计所需空间。
- 无法获知输入大小或目标提供者无法报告空间时允许启动；写入失败后按既定规则清理半成品。

代码兼容性直接确定：FST-TEXT1 的 UTF-8 明文上限保持与 Java `OfflineCryptoService.MAX_TEXT_BYTES` 一致，为 16 KiB。

### 23. 文本结果不自动复制

- 加密或解密成功后，结果显示在只读输出框。
- 不自动写入系统剪贴板。
- 仅在用户点击“复制”按钮后写入剪贴板。

### 24. 不自动清除剪贴板

- 用户复制解密明文后，应用不设置自动清除计时器。
- 加密载荷同样不自动清除。
- 剪贴板内容由用户和 Android 系统管理。

### 25. 后台保留文本解密内容

- 应用进入后台时不清空 FST-TEXT1 解密输入。
- 不清空已经显示的解密明文。
- 返回应用后继续显示原内容。
- 进入后台仍会按第 4 项清除私钥解密授权；该授权清除只影响新的解密操作，不隐藏已显示内容。

### 26. 不限制屏幕捕获

- 文本解密页面不启用 `FLAG_SECURE`。
- 允许系统截图和录屏。
- 允许解密页面出现在系统最近任务预览中。

### 27. 不持久化文本内容

- 不保存文本加解密历史。
- 不将文本输入、密文输出或解密明文写入数据库。
- 内容只允许保存在当前应用进程内，以支持页面切换和短暂后台。
- 应用进程终止或应用重新启动后不恢复这些内容。

### 28. 解密失败提示

- 当前私钥无法解密 FST2/FST-TEXT1 时，显示：
  - “无法解密：内容可能不是使用本机当前公钥加密，或内容已经损坏。请让发送方使用你当前导出的公钥二维码重新加密。”
- 不向普通用户显示 `BadPaddingException`、OAEP、堆栈或内部算法细节。
- 不断言失败一定由密钥不匹配造成。
- 本地调试日志不得包含私钥、AES 会话密钥、明文或完整密文。

### 29. 无密钥时允许进入应用

- 首次安装且没有密钥时不强制生成密钥。
- 应在应用中明确提示“当前没有密钥”。
- 仍允许管理联系人、修改设置，以及使用联系人或临时二维码公钥加密。
- 禁用文件解密、文本解密和“加密给自己”。
- 依赖本机私钥的入口应提示用户前往密钥页生成密钥。

### 30. 中英文与默认语言

- 应用仅需支持英文和中文。
- 全新安装默认使用英文，不根据系统语言自动选择中文。
- 设置页允许用户选择 English 或中文。
- 用户选择必须持久保存，后续启动继续使用上次选择。
- 本项覆盖 `handOff/2026-07-03-android-app-handoff.md` 中“跟随系统”的旧默认方案。

### 31. 语言立即切换

- 用户在设置页选择语言后，整个应用界面立即更新。
- 不要求用户手动退出或重启应用。
- 使用 Android 官方应用语言 API 管理 locale 和资源重建。
- 持久保存语言选择。

### 32. 主题设置

- 提供“跟随系统、浅色、深色”三项。
- 全新安装默认跟随系统。
- 用户选择持久保存。
- 切换后立即生效。

### 33. 禁用系统备份与迁移

- 完全禁用 Android Auto Backup。
- 禁用设备到设备应用数据迁移。
- 联系人数据库、设置和应用私有文件均不进入系统备份。
- 新设备或重装后始终作为全新本地实例。

由“纯本地、不连接服务器”的既定目标直接确定：

- Manifest 不申请 `INTERNET` 权限。
- 不集成使用统计、远程崩溃上报、广告 SDK 或在线更新检查。
- 诊断信息仅保留在本机。

### 34. 联系人数据库不二次加密

- Room 数据库不引入 SQLCipher。
- 不设置独立数据库密码。
- 数据库只存联系人显示名、公钥、指纹及必要时间字段。
- 不在数据库中存私钥、文本历史或文件明文。
- 依靠 Android 应用沙箱和设备文件级加密保护。

### 35. 无安全锁屏时禁止生成密钥

- 设备未配置安全锁屏时，不允许生成本机密钥。
- 可接受的系统认证包括 PIN、图案、密码或生物识别。
- 应提供跳转 Android 安全设置的操作和返回后的重新检测。
- 无本机密钥期间仍允许使用联系人或临时二维码公钥进行加密。

### 36. 生物识别变化不使密钥失效

- 新增或删除指纹/面容时，不主动使现有私钥失效。
- 用户仍可通过当前生物识别或设备 PIN、图案、密码验证。
- 仅在 Android Keystore 因安全锁屏移除、凭据重置或硬件异常而报告永久失效时，将密钥视为不可用。

### 37. 永久失效密钥的恢复

- Keystore 报告私钥永久失效后，停止文件/文本解密。
- 禁用“加密给自己”。
- 显示该私钥不可恢复、历史密文可能永久无法解密的说明。
- 用户通过系统身份验证和二次确认后，可以删除失效密钥记录。
- 删除后允许用户手动生成新密钥。
- 不自动删除失效密钥，也不自动生成替代密钥。

### 38. 公钥二维码输出位置与名称

- 公钥二维码 PNG 保存到 `Downloads/FileSecurity/`。
- 文件名为 `fst-public-key-<公钥指纹末8位>.png`。
- 重名时追加 `(1)`、`(2)` 等递增编号。
- 永不覆盖已有二维码文件。

### 39. 公钥二维码系统分享

- 导出成功后显示二维码预览和保存路径。
- 提供“在文件管理器中打开”按钮。
- 提供“分享 PNG”按钮，通过 Android 系统 Sharesheet 分享。
- 应用自身不实现上传、消息发送或网络传输。

### 40. 仅分享加密结果

- `.fst2` 文件加密成功后提供显式“分享”按钮。
- `FST-TEXT1:` 文本加密成功后提供显式“分享”按钮。
- 绝不自动打开分享面板或发送内容。
- 解密后的明文文件和文本不提供分享按钮。

### 41. 接收系统传入的密文

- 注册打开 `.fst2` 文件所需的 Android Intent 处理。
- 从文件管理器打开 `.fst2` 时进入文件解密页并选中该 URI。
- 接收其他应用分享的 `FST-TEXT1:` 纯文本。
- 收到文本后进入文本解密页并填入输入框。
- 外部 Intent 只预填输入，不自动解密。
- 用户仍须主动点击解密并完成系统身份验证。

### 42. 严格要求 `.fst2` 并与 macOS 双向兼容

- 文件解密必须先要求输入文件具有 `.fst2` 扩展名。
- 扩展名通过后仍须验证 FST2 magic、版本、算法标识、长度边界和认证标签，不能只信任文件名。
- Android 与 macOS 离线文件加解密必须双向互通：
  - Android 加密的 `.fst2` 可由 macOS 解密；
  - macOS 加密的 `.fst2` 可由 Android 解密。
- FST2 内部结构、规范化 CBOR、块大小、AAD、nonce 派生和算法参数以现有 Java/macOS 实现为兼容基准，不建立 Android 变体。
- Android 的 RSA-OAEP 必须显式指定 SHA-256 与 MGF1-SHA256，不能依赖 Provider 默认 MGF1 参数。
- 同样维持既有 FST-TEXT1 双向兼容要求。
- 发布验收必须包含跨平台双向的文件与文本测试向量。

### 43. `.fst2` 扩展名不区分大小写

- 输入扩展名检查不区分大小写。
- 接受 `.fst2`、`.FST2` 和混合大小写。
- 新生成的加密文件始终使用小写 `.fst2`。

必要安全校验：解密时不得直接信任容器头中的原始文件名。必须去除路径、`..`、路径分隔符、控制字符和非法名称，只使用安全的基本文件名，防止目录穿越或覆盖非目标文件。

### 44. 解密结果不自动打开

- 文件解密成功后不自动打开明文文件。
- 结果页显示文件名、文件大小和完整保存路径。
- 提供“打开文件”按钮。
- 提供“在文件管理器中打开”按钮。
- 两种外部操作都必须由用户明确触发。

### 45. 联系人排序与搜索

- 默认按显示名依据当前应用语言环境升序排序。
- 显示名相同时按完整公钥指纹排序，保证稳定次序。
- 提供联系人搜索框。
- 搜索支持匹配显示名和公钥指纹任意连续片段。
- 搜索忽略大小写和用户输入的指纹空格。

### 46. 禁止重新导出联系人公钥

- 只有本机自己的公钥可以导出为二维码 PNG。
- 联系人详情显示名称和完整公钥指纹。
- 不提供联系人公钥导出、复制或系统分享。

### 47. 允许更新联系人公钥

- 允许在现有联系人记录上更新公钥。
