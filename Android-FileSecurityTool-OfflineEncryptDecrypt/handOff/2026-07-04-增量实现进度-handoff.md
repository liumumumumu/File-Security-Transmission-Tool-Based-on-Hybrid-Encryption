## 当前已完成改动

- Gradle `namespace`、`applicationId` 和 Kotlin 包声明已统一为 `com.filesecuritytool.android`；源文件目录尚保留原路径，不影响 Kotlin 编译。
- FST2 定长读取已从 Android 13 才支持的 `InputStream.readNBytes` 改为兼容 Android 12 的 `DataInputStream.readFully`，并保留截断校验。
- Room schema 已生成到正式包名对应路径。
- 密钥页已切换到已有的新 `HardwareKeyStore`、`PublicKeyQrExporter` 和 `feature/keys/KeyViewModel`：
  - 不再显示私钥导入、私钥导出或私钥二维码；
  - 已有密钥时不显示生成入口；
  - 显示公钥指纹和 StrongBox/TEE；
  - 删除前显示永久不可解密警告，再调用生物识别或设备凭据；
  - 公钥仅通过二维码 PNG 导出。
- `KeyViewModel` 的删除操作增加 busy/error 状态处理。
- 已补充安全锁屏前置检查：
  - `HardwareKeyStore.generate()` 在无安全锁屏时拒绝生成；
  - 密钥页显示本地化说明和“打开系统安全设置”；
  - 从系统设置返回时重新检测锁屏状态；
  - `AppContainer` 将 application context 注入 `HardwareKeyStore`。
- 文件任务处于 `Running` 时，密钥删除入口和确认按钮均禁用；系统认证返回时再次检查任务状态，避免认证期间新任务启动造成竞态删除。
- StrongBox 生成遇到 `StrongBoxUnavailableException` 或 Provider 明确生成失败时，清理可能的别名后回退 TEE；生成完成后仍通过 `KeyInfo` 拒绝软件级密钥。
- 公钥二维码导出成功卡片现已显示：
  - Downloads/FileSecurity 下的保存路径；
  - 二维码 PNG 预览和完整公钥指纹；
  - 用户主动触发的外部打开操作；
  - 通过 Android Sharesheet 分享 PNG，且仅授予临时只读 URI 权限。
- 对照 Java `KeyArtifactPayload`、`PublicKeyPayloadService` 和兼容测试后，Android 公钥二维码输出已固定为 handoff 指定的紧凑 `FST-PUB1:<X.509 DER Base64>`。解析端同时兼容：
  - `FST-PUB1`；
  - Java 当前生成的 `FST-KEY1` public JSON；
  - Java API 包装的 `{"qrText": ...}`。
- `CryptoCompatibilityTest` 已覆盖上述三种公钥载荷；RSA-OAEP 仍显式使用 SHA-256 和 MGF1-SHA256。
